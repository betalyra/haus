Your paging tool from the [tour](/docs/tour) logs every page. Logs grow forever, get tailed live and read by other tools. In haus, **every file is already a stream**: no second format needed.

<Story types>

<Step label="pages.haus" code={steps[0]}>

### One page, one entry

An entry is a value like any other, **followed by a comma**. Every entry gets one, the last one too.

</Step>

<Step label="pages.haus" code={steps[1]}>

### New entries go at the end

Append and you're done. No array to reopen, no bracket to move.

> `>>`, `tail -f` and `cat a.haus b.haus` all keep the file valid.

</Step>

<Step label="pages.haus" code={steps[2]}>

### A new kind of entry

You add escalations. Tools that only know `Paged` and `Acknowledged` read `Escalated` as **Unknown** and carry on.

</Step>

<Step lang="ts" label="watch.ts" code={steps[3]}>

### Read as it arrives

The comma tells the reader an entry is complete, so it hands each one over **right away**. Memory stays bounded by the largest entry.

</Step>

<Step lang="ts" label="watch.ts" code={steps[4]}>

### Was the connection cut?

A dropped connection could leave `100` where `1000` was meant. **Strict mode** requires the last comma, and reports a truncated stream instead.

</Step>

<Step lang="ts" label="watch.ts" code={steps[5]}>

### Typed entries

With a schema, each entry is checked as it arrives. `OpenVariant` lets new kinds through as `Unknown`.

</Step>

</Story>

## Good to know

- Encoders write streams **one entry per line**, so `grep` and `wc -l` work like on NDJSON, and it's still haus.
- A single document is a stream of one. A reader that expects one value rejects two.
- In a schema, `type Root = Stream Entry` says the file is a stream.
