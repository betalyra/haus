The paging tool needs the team in its code, typed. You already have the schema from the [tour](/docs/tour); here's where it goes.

`team.haus` is checked against `team.schema.haus` next to it, in your editor as you type. Hover a type name to see it.

<Step lang="ts" label="pager.ts" code={steps[1]}>

### Import it in TypeScript

With `@haus-fmt/import`, a `.haus` file **imports like a module**: typed by its schema, checked on load.

Variants arrive as tagged objects, so TypeScript knows only Slack contacts have a `user`.

</Step>

<Step lang="ts" label="pager.ts" code={steps[2]}>

### Already using Zod?

`parseWith` reads haus with **any Standard Schema** library: Zod, Valibot, ArkType, Effect. Keep your types, swap the format.

</Step>

<Step lang="rust" label="main.rs" code={steps[3]}>

### Rust, generated

`haus-build` turns the schema into Rust types at build time. Variants become **enums**, and `match` makes you handle every case.

</Step>

<Step label="team.haus" code={steps[4]}>

### A broken file

Alan's Slack contact lost its `user`. Decoding stops and says **what** is wrong and **where**. Your editor said so first.

</Step>

</Story>

## Which one to use

- **TypeScript, new project:** typed imports, or build schemas in code with `@haus-fmt/haus/schema`.
- **TypeScript, existing schemas:** `parseWith` with the library you already use.
- **Effect:** `@haus-fmt/effect`.
- **Rust:** `haus-build` in `build.rs`.
