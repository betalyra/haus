# haus for Roc

Built against the Roc nightly compiler (2026-11-03) and basic-cli 0.26.0.

| Path | Contents |
|---|---|
| [`package/`](package) | The haus package: `Value` (data model and parser), `Decode`, `Encode` (compact writer), `Int` (integers of any size), `Stream` (reads a stream chunk by chunk), `Time` (the std/time profile) |
| [`examples/`](examples) | The same examples as in TypeScript and Rust, on the same files in [`../examples`](../examples), plus `shop`, a Roc showcase |
| [`schema-test/`](schema-test) | Generated: the schema conformance suite ([`../test-suite/schema`](../test-suite/schema)) as Roc tests |

## Examples

| Example | Shows |
|---|---|
| [`quickstart`](examples/quickstart) | `thread.haus`: typed data, decoding, encoding, errors |
| [`order`](examples/order) | `order.haus`: schema packages (`@haus/money`, `@haus/geo`) and codecs |
| [`logs`](examples/logs) | `logs.haus`: a stream, read chunk by chunk and written back |
| [`shop`](examples/shop) | Roc's structural types: handlers for any union or record with certain tags or fields (row polymorphism) |

Run each from its folder, because the examples read the shared files by relative path:

```sh
cd examples/quickstart && roc main.roc
cd examples/order && roc main.roc
cd examples/logs && roc main.roc
```

## Generated modules

Each example's types and decoders come from its schema, like in TypeScript
(content mapper) and Rust (`haus-build`). Roc has no build scripts, so the
modules are generated by `haus-gen` and checked in, like protobuf output:

| Schema | Module |
|---|---|
| `thread.schema.haus` | [`quickstart/Thread.roc`](examples/quickstart/Thread.roc) |
| `logs.schema.haus` | [`logs/Logs.roc`](examples/logs/Logs.roc) |
| `order.schema.haus` | [`order/Order.roc`](examples/order/Order.roc), and [`order/Typed.roc`](examples/order/Typed.roc) with codecs |
| `@haus/money`, `@haus/geo` | [`HausMoney.roc`](../extensions/money/roc/HausMoney.roc), [`HausGeo.roc`](../extensions/geo/roc/HausGeo.roc): Roc packages next to the npm and Cargo ones |

After changing a schema, regenerate them (`haus-gen` is part of
[`haus-build`](../rust/haus-build), so this needs Rust):

```sh
examples/gen.sh
```

| haus | Roc |
|---|---|
| `{ a: T, b?: U }` | `{ a : T, b : [Missing, Present(U)] }` |
| `< A \| B T \| C { … } >` | `[A, B(T), C({ … }), Unknown(Str, List(Value))]`, without `Unknown` when closed |
| `Maybe a`, `Result e a` | `[None, Some(a)]`, `Try(a, e)` |
| `Array a`, `Map v` | `List(a)`, `List((Str, v))` |
| `Int`, `Int8`…`UInt64`, `Float32`, `Float64` | `Int`, `I8`…`U64`, `F32`, `F64` |
| `Decimal`, `Date`, `Instant`, … | `Str`: exact text, std/time checked by its profile |
| `< >` | `[Bare(Str), Other(Str, List(Value))]`: any variant, kept as it was |
| `type Pair a = …` | `Pair(a)`, decoded with `decode_pair(v, decode_a)` |
| `Any` | `Value`: any value, as parsed |
| `Secret a` | `Secret(a)`: `Str.inspect` and `dbg` show `<redacted>`; `.expose()` gives the value |
| `@deprecated("why")` | a `## Deprecated…: why` line in the type's doc comment (Roc has no deprecation marker) |

Named variants are nominal (`:=`), and so are records that refer to
themselves (`Tree := { name : Str, children : List(Tree) }`). A type named
like a Roc builtin or an imported module gets a `_` in Roc (`type List a`
is `List_(a)`, `type F64 = Float64` is `F64_`); its functions keep their
names (`decode_list`).

A `Secret` is written in full when encoded, but a decode error inside it names
only its place and type (`.pin: not a valid Secret Int (the value is hidden)`).

`Encode.to_str` (and `Encode.stream`) check what they write, so they return
a `Try(Str, Encode.Error)`. What a generated encoder gives is always fine;
what can fail is a `Value` built in code, the raw value of an `Any` or an
unknown variant (spec §9.8): `Num("abc")` is an error (`.extra: not a number
literal`), as are a tag that isn't a tag name, a key used twice in a record,
and nesting, strings and numbers beyond the parser's limits. Number literals
are written as the parser reads them (`Num("1E5")` as `1e5`).
`Encode.message(e)` gives the error with its path.

A float is written in one spelling (spec §15): the fewest digits that read
back as the same `F64` or `F32`, laid out like JavaScript (`0.1`, `1e21`,
`1.5e-7`, `-0`). A number too large for the type is a decode error.

`Int` (the package's `Int` module) is an integer of any size, kept as its digits
and written back unchanged, like `haus::Int` in Rust. `to_i64` / `to_i128` convert
it and fail with `OutOfRange` when it doesn't fit. For a native integer that must
fit, the schema says `Int64` (out of range is a decode error).

A codec is a Roc module with a `Target` type, `decode : Base -> Try(Target, Str)`
and `encode : Target -> Base` ([`Cents.roc`](examples/order/Cents.roc)), chosen
with `--codec ID=MODULE` when generating.

## Tests

```sh
cd package && roc test ConformanceTest.roc && roc test TimeTest.roc
cd package && roc test Decode.roc && roc test Encode.roc && roc test Int.roc && roc test Stream.roc
cd examples/shop && roc test main.roc
cd schema-test && roc test main.roc
```

`ConformanceTest.roc` is generated from `../test-suite` by
`scripts/gen_conformance.py`, and `TimeTest.roc` holds the same std/time
cases as the TypeScript and Rust bindings.

[`schema-test/`](schema-test) runs the schema conformance suite
(`../test-suite/schema`, spec §15): `scripts/gen_schema_conformance.py`
generates a module per schema with `haus-gen` (so it needs Rust) and
`SchemaTest.roc` with one `expect` per case. A schema with attributes also
gets a module generated without them (`AttributesBare.roc`), which must give
the same results (attributes don't matter, spec §15). Re-run it after changing
the suite or the generator:

```sh
python3 scripts/gen_schema_conformance.py
```
